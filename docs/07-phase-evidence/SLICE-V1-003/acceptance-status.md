# SLICE-V1-003 — acceptance status

Two hundred criteria, each read against the repository and then challenged.
Every claim of VERIFIED was put to a second reader who opened the cited
evidence; eight did not survive that and were lowered. The counts below are
after those corrections, not before.

| Status | Count | What it means |
| --- | --- | --- |
| VERIFIED | 46 | a named passing test or an artefact somebody opened demonstrates it |
| PARTIAL | 133 | some of it is demonstrated and a named part is not |
| NOT_YET | 21 | nothing in the repository demonstrates it |

## No engineering closure claim is made

`CLOSED_ENGINEERING_WITH_DEFERRED_RELEASE_OBLIGATIONS` is the only claim this
Slice may make, and it requires all two hundred criteria executably verified.
They are not: 133 are partial and 21 have nothing behind them yet. The
deferred obligations are recorded separately in `deferred-release-register.json`;
what follows is the engineering work that remains, not an external dependency.

## What is not yet demonstrated at all

- **S3-AC-047** — missing/conflicted Freshness Profile blocks only affected purposes and cannot erase an independent Fresh danger.
  - Nothing resolves or evaluates a Freshness Profile at runtime (AdvertisingPolicyRepository.resolveFreshness has no callers), so purpose-scoped blocking cannot be observed; the nearest analogue, AdLaneResolverTest#TC-ADV-LANE-002, proves only that a data-defect blocker cannot silence a proven loss, and a test seeding profiles for some purposes only and asserting that a Fresh danger still raises Protection would demonstrate this criterion.
- **S3-AC-065** — page open or free-text acknowledgement cannot satisfy the action stage.
  - There is no advertising action-stage record at all: the schema constraint that makes this true for availability (availability_case_event_action_shape_ck in V0030, requiring action_kind, action_evidence with a reference and an actor) has no advertising equivalent, and an ops.ad_case_event table with the same required shape plus a test would demonstrate it.
- **S3-AC-067** — reassignment preserves Case age and SLO history.
  - No assignment or reassignment concept exists for an advertising case — mart.ad_case (V0038:183-239) has no assignee column and there is no advertising case-event history — so an assignee column plus an append-only event log preserving first_observed_at-based age and prior SLO stages would be needed to demonstrate it.
- **S3-AC-068** — outside coverage, staffed-clock handling and `OUT_OF_COVERAGE_ACTIVE_HARM` exposure remain simultaneously visible.
  - staffed_coverage_enabled/timezone/start/end and out_of_coverage_visible_from_minutes are stored in core.ad_human_slo_profile and read into AdvertisingPolicyRepository.HumanSlo but are never consulted by any caller, and the literal OUT_OF_COVERAGE_ACTIVE_HARM appears only in a V0038 comment and in the contract and design documents, never in code, schema or a view.
- **S3-AC-070** — Protection/Regression targeted update meets P95 <= 5 minutes and hard <= 15 minutes; other targeted state update meets hard <= 15 minutes.
  - AdvertisingSlo declares CRITICAL_DISTRIBUTION_TARGET (5 minutes), HARD_BOUND (15 minutes) and TARGET_PERCENTILE, and AdvertisingTargetedWorker.recordLatency writes ops.ad_slo_observation with a breached flag computed from the hard bound, but AdvertisingSlo.missedCriticalTarget has no caller, no percentile is computed anywhere, and no test exercises the latency recording — a measurement over recorded observations plus a test would be needed.
- **S3-AC-071** — full reconciliation succeeds at least hourly and repairs a dropped targeted trigger while preserving any SLO violation.
  - AdvertisingReconciliationWorker.sweep and AdvertisingRecalculationRepository.repairCoveredRequests exist and AdvertisingWorkerProperties.sweepInterval defaults to one hour, but no test instantiates the advertising sweep at all — AdvertisingEfficiencyFlowIT calls the shared refresh seam directly and its comment at line 567 says the worker is "covered separately", which it is not (contrast AvailabilityRecalculationLoopIT and AvailabilityReconciliationWorkerTest for availability).
- **S3-AC-072** — Accepted Exception preserves the calculated lane and exact known consequence.
  - No advertising Accepted Exception exists: there is no ad_*_exception table in V0036-V0053, no service and no endpoint, and ops.availability_accepted_exception (V0030:1275) is bound by foreign key to availability cases; only the ADVERTISING_EXCEPTION_REQUEST action scope code in V0036:54 has been created.
- **S3-AC-073** — Exception requires exact cause/scope, evidence, consequence, Operations endorsement, Owner approval, period, review and Bundle.
  - Nothing in the repository records an advertising Exception's cause, scope, evidence, consequence, Operations endorsement, Owner approval, period, review or Bundle — an advertising accepted-exception table with those columns and their check constraints, plus a test, would be needed.
- **S3-AC-074** — valid Exception pauses only matching ordinary Action SLO, suppresses duplicate work visibly, cannot coexist with action intent, and invalidation reopens the same Case without automatic renewal.
  - With no advertising Exception entity there is nothing to pause an Action SLO, suppress duplicate work, refuse coexistence with an action intent, or reopen a Case on invalidation; the availability equivalent in V0030 is not reachable from an advertising case.
- **S3-AC-149** — reenablement never restores old decision assets.
  - Nothing invalidates prior decision assets on reenablement: AdvertisingContainmentRepository.reenable() only sets state, endorser, approver, reenabled_scope and reenabled_at, mart.ad_case supersession (V0044) is driven solely by the cause no longer calculating, and a PENDING ops.ad_bid_command that survived the stop would pass the gate again once containment clears — a test that reenables a containment and shows the pre-stop command, candidate and recommendation refused rather than resumed would demonstrate it.
- **S3-AC-154** — material confounder keeps early safety Guard active but blocks action-specific final verdict.
  - The only occurrence of 'confounder' in the backend is the recalculation trigger class 'CRITICAL_SALES_OR_CONFOUNDER' in V0038; there is no material-confounder state, no column on core.ad_outcome_policy or ops.ad_outcome_observation, and nothing that keeps the early Completed-Sales Guard active while blocking an action-specific final verdict — a confounder state plus a test showing the Guard still evaluating while the verdict is withheld would demonstrate it.
- **S3-AC-156** — operational association and causal incrementality remain separate.
  - No causal or incrementality construct exists to be kept separate — grep finds 'incrementality' only in the criteria documents, there is no holdout, uplift or counterfactual basis (V0049 ad_outcome_policy_basis_ck admits only two pre-change bases), and nothing labels an OPERATIONAL verdict as associative; a marker on the observation distinguishing association from a causal claim, plus a test, would demonstrate it.
- **S3-AC-160** — `VERIFIED_AD_RISK_CLEARED` proves only the original advertising danger cleared.
  - `VERIFIED_AD_RISK_CLEARED` appears nowhere in the repository; the advertising outcome vocabularies are OutcomeEvaluation.Verdict (IMPROVED/UNCHANGED/REGRESSED/INDETERMINATE/NOT_YET_EVALUABLE) and DualAxisVerdict.Outcome, neither scoped to the original danger — the nearest mechanism is the cause-specific plan (V0050 ad_outcome_policy.cause_code), and a cause-scoped terminal state with a test would be needed.
- **S3-AC-161** — `VERIFIED_AD_EXPOSURE_STOPPED` proves only no new dangerous exposure under complete evidence.
  - `VERIFIED_AD_EXPOSURE_STOPPED` appears nowhere in the repository, and no state asserts 'no new dangerous exposure under complete evidence' — a terminal state that requires CANONICAL_CONFIRMED evidence over the exposure window, with a test, would demonstrate it.
- **S3-AC-171** — Gate EV is exact Platform+Store+Capability+object+direction+basis+value+window+exposure+actor+abort authority and cannot authorize another scope.
  - No Gate EV authority object exists: the only carrier is ops.ad_decision_policy_bundle.gate_scope_reference (V0041), a free text column bounded only by length 1..256, and value, window, actor and abort authority are not part of any authorization record — deferred-release-register.json records S3-REL-016 and gate_ev NOT_AUTHORIZED, so a structured, scope-checked Gate EV envelope plus a test that it cannot authorize an adjacent scope is what would demonstrate it.
- **S3-AC-172** — Gate E consumes operating foundation, Shadow, direction-specific Gate EV, failure controls, early safety, ownership and aggregate Exposure.
  - There is no Gate E artefact, evidence bundle or consumption check anywhere in the repository — deferred-release-register.json records gate_e NOT_AUTHORIZED and defers the layered Pilot Evidence Bundle as S3-REL-018; a Gate E record naming the operating foundation, Shadow, direction-specific Gate EV, failure controls, ownership and aggregate exposure, with a test, would demonstrate it.
- **S3-AC-182** — Daily Action Brief is produced each configured operating day as a versioned `as_of` action snapshot.
  - Nothing named daily brief, action brief or as_of snapshot exists anywhere — grep for daily_brief/daily_action/DailyBrief across all migrations, backend and frontend returns nothing — so a versioned as_of Daily Action Brief table plus a producing job and a test that a configured operating day yields exactly one version would be needed.
- **S3-AC-183** — Weekly Evidence Review covers Shadow, actions, verification, SLO, outcomes, Regression, exposure, Bundle/Gate maturity and release obligations.
  - No Weekly Evidence Review artefact, table, endpoint or component exists (grep for weekly_review/weekly_evidence/WeeklyReview returns nothing across migrations, backend and frontend); demonstrating this needs a weekly versioned review projection covering the ten named sections and a test that it is produced.
- **S3-AC-184** — Daily/Weekly artifacts link canonical Cases/Tasks/Metrics/Outcomes and cannot become parallel writers.
  - There are no Daily or Weekly artifacts to link or to constrain, so neither the canonical linkage nor the read-only/no-parallel-writer property can be shown; the SoleAuthorityArchitectureTest#TC-AUTHORITY-001 pattern would be the way to prove the no-parallel-writer half once the artifacts exist.
- **S3-AC-185** — late facts create explicit Daily/Weekly revision or Delta lineage without overwriting prior publication.
  - No published Daily or Weekly report exists, so no revision or Delta lineage table, no as_of/source-cutoff preservation and no late-fact test exists anywhere in the repository.
- **S3-AC-197** — performance evidence proves targeted SLOs and hourly reconciliation at declared capacity.
  - AdvertisingSlo declares the bounds as constants and V0038 creates ops.ad_slo_observation, but no load has been applied and no reconciliation timing exists — docs/07-phase-evidence/SLICE-V1-003/executable-evidence.md says so plainly; a capacity harness recording P95 internal latency per lane against CRITICAL_DISTRIBUTION_TARGET/HARD_BOUND and hourly reconciliation completion at declared volume would demonstrate it.
