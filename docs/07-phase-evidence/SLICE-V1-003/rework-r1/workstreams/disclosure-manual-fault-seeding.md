# Disclosure, identity and human execution fault-seeding

This workstream separates four kinds of evidence. Pure frontend tests check exact wire states and user affordances with explicit response fixtures. PostgreSQL integration tests exercise the application role, canonical records, real constraints and the isolated proof issuer. Actual browser r3 exercises real servlet/JWT/IAM/SQL delivery and interactions; only its frontend OIDC exchange is intercepted. Lane and history fixtures are explicitly synthetic projection/read oracles and do not establish Provider semantics or economic calculations.

Caller-controlled role, actor, evidence grade and arbitrary intended-state JSON are absent from the human action request schema. PostgreSQL consumers derive actor identity and role grants from a current, one-use issuer proof; frontend assertions alone are not claimed as that security proof. Partial response parsers fail explicitly rather than silently shortening a finite candidate set. No accepted Contract or Frozen Finding is modified; production write remains disabled.

Browser r3 receipt binds source-input hashes, sanitized synthetic data identities, timestamps, runtime resources and output hashes. It contains no access tokens or generated database credentials. Root must still bind the final commit/tree and exact remote CI; no finding is marked closed by this workstream document.

Browser r3 is **8 passed / 3 failed**, not acceptance. API Maker and Ops actions passed; Owner preview hit a legacy DIAGNOSTIC_VIEW guard. Both Manual journeys completed the independent configuration proof and recorded an early observation, but the unchanged packet version left the Outcome component stale. The preview guard now uses the advertising scope and exact financial evidence gate; the UI remounts the Outcome query on a successful human action. A stable-version frontend regression covers the second fault. Rerun remains pending.
