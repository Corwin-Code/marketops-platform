# Manual configuration evidence completeness rework

The final source-to-clause review found an existing implementation gap in
Contract §6.13, S3-AC-081–082 and S3-DR-007 verification clause 2. The independent
verification route accepted only a native value and assigned submission time as
observation time. A matching value could therefore become configuration proof
without identifying the observation source, completeness or actual observed-at
time. The existing self-report and evidence-grade forgery tests did not exercise
that live independent-verification boundary.

This is an in-scope correction to the accepted requirement. Neither the accepted
Contract, Frozen Finding Set nor historical Controller disposition is amended.
The source review identified a feasible path; it is not presented as a separately
executed exploit against the old checkpoint.

The repair requires an explicit observation envelope bound to the exact packet,
native object, field, semantic profile, source and actual observation time.
Complete, explicitly attested direct official-console observations use the
existing governed independent-verifier route. Screenshot evidence remains
configuration-unverified. Missing metadata must never default to complete or
fresh. Grade is derived by the server. Current and historical proof eligibility
must preserve the difference between a timely observation and later Outcome
evaluation, without rewriting historical evidence.

Forward migration V0073, application/SQL enforcement, the console and actual
positive/adverse tests now implement the envelope together. Current proof,
release, exposure, Outcome scheduling and Task journal readers share the durable
qualification rule. A historical value-only record remains readable without
qualifying for new authority. Observation ordering preserves newer qualified
proofs and refuses to clear later uncertainty with older favorable evidence.

Later uncertainty reopens the original released reservation when available. If a
new intervention already holds overlapping scope, an Execution Integrity hold
preserves that holder and both factual histories. The forward index replacement
allows this historical state while a serialized issue-time guard preserves the
original refusal of new instructions against issued or unresolved packets. The
shared execution reservation and overlap checks remain authoritative.
