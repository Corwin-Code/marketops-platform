# Listing Action purpose and use basis

In Description preparation, select the actual purpose: formal conversion
improvement, independent description correction, or bounded manual exploration.
The backend resolves the accepted calibration for that exact purpose. Selecting
a purpose does not qualify the required safety, business evidence or execution.
A legacy request omitting the new field retains its prior formal-improvement
preparation behavior; historical Action facts are not backfilled.

For correction or bounded exploration, provide the evidence reference, continued
use conditions and ending/reassessment conditions. Bounded exploration also
requires an explicit finite future use deadline with a timezone and uses MANUAL.
Correction may have an applicable deadline; the software does not invent one
for every correction. The Action and Recommendation freeze the exact basis.
Changing the original basis or extending its deadline in place is refused.

The independent review page shows the complete Russian before/after text and
the same purpose basis. Review the use conditions together with the declared
change. The review digest binds both. Nonformal review records a purpose-basis
digest and does not claim a formal-improvement evaluation plan or result.
Formal review continues to require its original frozen evaluation plan.

Expiry never by itself certifies failure, restores a description, exits a
promotion or releases residual obligations. Java and V0118 now require the exact
frozen plan for formal purposes; correction and bounded manual exploration bind
the reviewed use basis with no formal plan. The launch row enforces the same
purpose/plan relationship and retains the exact execution Guardrail ID. The
application passes that ID to the current six-argument SQL launch function; the
historical five-argument entry is not executable by the application role.
Invocation proof consumption occurs after allowance lock waits, and current
Listing scope authority uses wall time.

Do not change an old basis to make it current or enable a platform worker as a
result of purpose handling. Existing default-OFF and Level 1 boundaries apply.

## Purpose-specific consumption

Purpose-specific preparation, review, approval and launch consume one frozen basis. Formal
conversion and promotion require their exact frozen plan; description correction
uses its correction basis; bounded exploration uses its finite conditions/deadline.
Promotion preparation also requires the exact selected qualified simulation, while
content actions cannot bind one.

Approval and launch re-read the current accepted purpose calibration, native scope,
canonical profit/return/unit-floor/supply protections and every selected simulation
dependency. An expired deadline, changed digest, missing plan, changed scope or
unqualified current protection prevents use. The launch transaction retains its
exact execution Guardrail identity and consumes its one-use proof after the existing
locks. No caller value can turn an unresolved protection into PASS. Purpose
handling does not authorize a Provider call, worker enablement, Gate-EV/Gate-E
or production write.
