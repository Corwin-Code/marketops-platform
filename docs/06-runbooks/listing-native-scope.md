# Listing native scope evidence

Local rework implementation; final Controller closure is pending.

An observed listing with mapped variants is not proof that all native members
have been acquired. In Listing Health, an authorized manual verifier records the
actual source boundary, native listing key, exact native member keys, source
observation time, source reference and scope-basis reference. Preserve opaque
keys and reference whitespace. Select whole listing or single native variant
according to the actual source. Do not fill missing members from assumptions.

Use PARTIAL when pagination or enumeration is incomplete and preserve the
continuation reference. COMPLETE requires an explicit total equal to the unique
native members and no continuation. UNKNOWN remains available when coverage
cannot be established. A single-variant observation never qualifies the full
listing. Intake is MANUAL_ENTRY and does not become marketplace Raw or an
independent commercial verification.

The declared verification expiry is an upper bound. An accepted calibration
package must also supply the applicable source-kind maximum age. Without that
rule, the scope remains unqualified. Reacquiring or rerecording an old source
preserves its observation time and cannot make it fresh. The test fixture's
3600-second parameter is fictional and is not a production recommendation.

Affected-set resolution composes this evidence with current canonical mappings.
Missing members, unresolved mappings, conflicting scope, stale evidence or
inactive products prevent COMPLETE. Correct mappings through the existing
product/listing identity workflow. Record later source observations as new facts;
old receipts and affected sets remain retained. Changed native membership or
mapping versions require dependency re-evaluation before an old approval can
be used. Unchanged evidence refresh does not itself enlarge the impact set.

A saved observation receipt confirms storage only. No platform operation,
launch allowance release, commercial Outcome or production enablement follows
from recording it. New platform writes remain default OFF.

The existing calibration digest now serializes timestamp values in UTC with an
explicit date style, so a scope snapshot cannot reinterpret acceptance according
to the caller's session time zone. Historical accepted bytes are not rewritten.
If an old acceptance hash differs, it remains unqualified for current use; this
change does not confer a new Owner acceptance or reconstruct historical evidence.
