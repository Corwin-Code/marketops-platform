# Listing calibration replacement and continuation

Prepare and professionally validate the exact replacement through the existing
calibration Console endpoints. An independent authorized Owner accepts and
activates that exact digest and explicit predecessor. Acceptance of a draft alone
does not change current authority. A replacement never edits an accepted package.

For a newly prepared Action, the service retains the rules it consumes. After a
replacement, current scope and purpose resolution rechecks that projection.
Unchanged dependencies can continue through the existing approval and launch
checks. The existing Guardrail record identifies both the original package and
the current package supporting this recheck. A changed rule or its source evidence
requires reprocessing of the affected action; the system does not borrow a new
approval or silently update the old plan.

A description action does not depend on promotion demand scenarios. A promotion
action does not depend on description serialization length or readback equivalence.
These are bounded exclusions derived from current consumers. Other parameters
remain bound. Future categories cannot silently expand the versioned projection.

An expired current package, unproved historical projection, changed native scope,
revoked approval, expired binding or containment still blocks the relevant work.
Continuity does not extend approval validity, revive an inapplicable binding,
release occupations, certify business success or authorize a Provider call.
Historical plans and results retain their original package and rules.

## Required categories by declared purpose

Calibration detail exposes `requiredCategories` from the existing Policy owner.
The professional supplies the categories actually required for the declared
purpose; absent optional growth fields are not filled with demonstration values.
For correction, material-improvement, promotion-demand and formal-growth-node
parameters are not required. Profit, return, scope, freshness, responsibility,
approval, allowance and description safety parameters remain necessary.

An accepted correction package resolves only for correction within its accepted
scope and effective period. It cannot satisfy a missing promotion package or
extend an expired period. Category completeness does not itself qualify sources,
prove a comparison method or authorize correction/exploration execution.

## Purpose-specific continuation

Preparation, review, approval and launch resolve the exact accepted category projection for
`LISTING_CONVERSION`, `DESCRIPTION_CORRECTION`, `BOUNDED_EXPLORATION` or
`PROMOTION`. Only formal purposes consume a frozen evaluation plan. Promotion also
binds its selected simulation package/version and complete context; correction
does not borrow promotion demand, and bounded exploration does not bypass current
profit/return/unit-floor/supply protection.

Continuation is allowed only when each actually consumed dependency is unchanged
and current. A new accepted package can support the recheck without rewriting the
historical Action, plan, simulation or review. Changed or unproved consumed rules,
sources, scope, purpose conditions or expiry keep the action inapplicable.
Package resolution does not authorize a provider operation or enable production.
